# jtl311linux loaded r09 endogenous host-load decision

## Observed failure

All four wave-9 loaded trajectories completed naturally and passed the GPU,
process-group, host-memory, and task-native progress checks. The safe runner
nevertheless rejected `cnn_after_rl` because Linux `load1 / nproc` reached
`0.786875`, above the former `0.5` threshold.

The hash-bound process snapshots covered the target interval and reported no
unapproved CPU process, no unapproved CPU snapshot total, and zero conservative
unapproved CPU exposure. The high aggregate load was therefore generated by
the registered RL resident and CNN target themselves, including their runnable
threads and checkpoint I/O.

## Resolution

Aggregate host load is retained in every continuous audit, including the
threshold comparison and violations, but is treated as an endogenous action
diagnostic rather than an external-contamination gate. The loaded action's
measured natural-completion time and split-conformal lower-service bound already
include this endogenous load.

The strict external-contamination conditions remain unchanged: complete
target-interval samples, idle non-assigned GPUs, only the two controlled GPU
process groups, sufficient host memory, and conservative unapproved CPU
exposure at or below the registered limit. Re-auditing the original wave-9
logs under this corrected semantics passes all four trajectories without
changing any service or completion observation.
